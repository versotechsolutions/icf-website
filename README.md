# International Conference Forum (ICF) website, Phase 1 frontend

Official website frontend for the **International Conference Forum (ICF)**, an academic and research conference organisation. Built by VersoTech Solutions.

> **Phase 1 is frontend only.** There is no backend, database, API, authentication, payment or email integration. Conference listings and all admin data are **development sample data**, labelled "Sample" in the UI. Client-supplied copy is used wherever it exists; see [docs/content-mapping.md](docs/content-mapping.md).

## Stack

- React 19 + TypeScript (strict) + Vite
- Tailwind CSS v4 (tokens in `src/styles/index.css`)
- React Router 7 (admin area code-split)
- lucide-react icons; self-hosted fonts (Source Serif 4, Public Sans)
- Dev tooling: sharp (asset optimisation), puppeteer-core (screenshots and smoke tests, using the installed Chrome)

## Getting started

Requirements: Node.js 20+ and npm.

```bash
npm install
npm run dev          # http://localhost:5173
npm run build        # type-check + production build to dist/
npm run preview      # serve dist/ at http://localhost:4173
```

Quality checks (run against `npm run preview`, using the locally installed Google Chrome; set `CHROME_PATH` if Chrome is elsewhere):

```bash
npm run test:smoke                               # 21 end-to-end interaction tests + internal link crawl
npm run screenshots -- http://localhost:4173 docs/screenshots   # full-page desktop + mobile captures
npm run assets                                   # regenerate optimised logo/favicon/photo from source-assets/
```

## Pages

| Area | Routes |
|---|---|
| Home | `/` |
| About | `/about` |
| Conferences | `/conferences`, `/conferences/:country` (SEO country pages, for example `/conferences/india`), `/topics`, `/event/:slug` (for example `/event/icicgb-26`) |
| For participants | `/registration`, `/paper-submission`, `/invitation-letter`, `/awards` |
| Conference information | `/call-for-papers`, `/programme`, `/faq`, `/venue`, `/travel`, `/video-conferencing` |
| Other | `/gallery`, `/contact`, `/policies/:slug` (privacy, terms, disclaimer, refund-cancellation), 404 |
| Admin (UI only) | `/admin/login`, `/admin` (dashboard), `/admin/conferences` (+ `/new`, `/:id/edit`), `/admin/registrations`, `/admin/payments`, `/admin/emails`, `/admin/reports`, `/admin/content`, `/admin/access` |

The admin login accepts any valid-looking email and password in this phase. It is reachable from the footer "Admin" link.

```
  services/        data-access layer (conferences.ts): swap for API calls in Phase 2
  hooks/           usePageMeta, useForm, useOnClickOutside
  utils/           validation, formatting, cn
  types/           shared TypeScript types
  styles/          design tokens and base styles
docs/              content mapping, design system, pending client items, testing report, screenshots
scripts/           asset optimisation, screenshots, smoke tests
```

## Ready for Phase 2

- **Data access is isolated.** Pages call `listConferences()` / `getConference()` in `src/services/conferences.ts`, which return Promises with pagination metadata. Replace their bodies with `fetch('/api/...')`; UI components do not change.
- **Filters live in the URL** (`?q=&topic=&month=&page=` and `/conferences/:country`), so server-side rendering or prerendering of country pages is straightforward.
- **Forms** use one `useForm` hook with schema rules (`src/utils/validation.ts`); add an API call in each `handleSubmit` callback.
- **Content** sits in `src/data/content.ts` and maps one-to-one to the admin "Conference content" fields.
- **Sample data** sits in `src/data/*.sample.ts` and can be deleted once real APIs exist.
